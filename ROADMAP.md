# AURA — Roadmap

Кроссплатформенный мессенджер со сквозным шифрованием (Web, Android, iOS) на Flutter.
Личный проект, до 20–30 пользователей онлайн.

- Дизайн: https://claude.ai/artifact/WtBLaG5DtxkVA1fVTxMwJ8
- Дизайн-система: https://claude.ai/artifact/WLmUZJx5LKwhhWQUZMoKMh

## Решения

| Что | Выбор |
| --- | --- |
| Клиент | Flutter (Web, Android, iOS), один код |
| Сервер | Dart: shelf + WebSocket |
| База | SQLite (WAL). Переход на PostgreSQL, если сервер станет многоэкземплярным или онлайн вырастет до сотен |
| Шифрование | Signal Protocol (X3DH + Double Ratchet), `libsignal_protocol_dart` |
| Ключи | Один ключ личности на аккаунт, как в Signal: новое устройство получает его от уже привязанного по QR-коду, сервер добавить устройство незаметно не может |
| Хостинг | Свой сервер в Docker, доступ из интернета через Cloudflare Tunnel (Zero Trust) |
| Сборка | GitHub Actions: Web, Android, iOS (iOS без подписи до появления Apple Developer аккаунта) |

## Структура репозитория

```
app/      Flutter-клиент
server/   Dart-сервер
.github/  CI
```

## Этап 1. Каркас приложения на трёх платформах

- [x] Flutter-проект в `app/`, сборка под Web, Android, iOS
- [x] Тема из дизайн-системы: Comfortaa + Ubuntu, палитра, светлая и тёмная тема
- [x] Экраны на тестовых данных: Приветствие, Вход, Регистрация, Чаты, Диалог, Настройки, Профиль
- [x] GitHub Actions собирает все три платформы

Готово, когда: приложение открывается в браузере, на Android и iOS, по экранам можно пройти.

## Этап 2. Сервер и живая переписка

- [x] Dart-сервер в `server/`: регистрация, вход, сессии
- [x] Доставка сообщений 1-на-1 через WebSocket, очередь для офлайн-получателей
- [x] SQLite: пользователи, сессии, очередь сообщений
- [x] Dockerfile и запуск через Cloudflare Tunnel на вашем домене
- [x] Экран Контакты: собеседники из переписки, новый находится только по точному никнейму
- [x] Запросы на переписку: первое сообщение нового контакта ждёт «Принять» или «Отклонить», до этого отправитель не видит «доставлено»
- [x] Смена никнейма в профиле: id аккаунта постоянный, ищут только по нынешнему @никнейму

Готово, когда: два человека на разных платформах переписываются через ваш сервер. Шифрование пока только транспортное (HTTPS).

## Этап 3. Сквозное шифрование

- [x] Android ходит только по HTTPS через туннель (`web.aura-msg.space`), HTTP запрещён, адрес сервера зашит в приложение
- [x] Ключи устройства: identity key, signed prekey, one-time prekeys; приватные ключи только на устройстве
- [x] Сервер хранит и выдаёт публичные prekey bundles
- [x] X3DH для установки сессии, Double Ratchet для сообщений
- [x] Сервер видит только зашифрованный текст
- [x] Сверка кода безопасности собеседника
- [x] Биометрическая блокировка приложения (Android, iOS; в браузере её нет)
- [x] ~~Каждое устройство входит по паролю и получает свои ключи~~ Один ключ аккаунта: новое устройство после пароля показывает QR-код (или текстовый код), старое сканирует его в «Настройки → Устройства» и передаёт ключ аккаунта в зашифрованном конверте. Сообщения шифруются для каждого устройства собеседника и копией для своих. История на новое устройство не переносится
- [x] Переход на один ключ: при первом запуске нового сервера ключом аккаунта становится ключ самого старого устройства, остальные устройства выходят, и их локальная переписка стирается (известная потеря, пользователь тогда был один)
- [x] Сервер проверяет подпись signed prekey ключом аккаунта; вход убирает брошенные привязки (дольше часа) и устройства без активности 90 дней, отвязка — только с привязанного устройства
- [x] Android: резервное копирование выключено (ключи Keystore в бэкап не попадают, а переписка в открытом виде не должна уходить в облако)
- [x] «Начать заново», если старых устройств не осталось: новый ключ аккаунта по паролю, остальные устройства выходят, у собеседников «Код безопасности изменился» и отправка ждёт подтверждения

Готово, когда: в базе сервера нет ни одного открытого текста сообщения.

## Этап 4. Медиафайлы

- [x] Файл шифруется на клиенте случайным ключом (AES-256-GCM), ключ уходит внутри E2E-сообщения
- [x] Сервер хранит зашифрованные файлы на диске (до 2 ГБ, грузятся частями по 8 МБ, удаляются через 30 дней)
- [x] Фото показываются в чате, любые файлы сохраняются на устройство
- [x] Голосовые сообщения
- [x] Видео с превью и сжатие фото перед отправкой
- [x] Удаление сообщений у себя и у всех: файлы стираются с устройств и с сервера
- [x] Фото и видео альбомом до 10 штук, галерея по дате

## Этап 5. Групповые чаты

- [x] Группы поверх попарных Signal-сессий (sender keys)
- [x] Создание группы, участники, админы
- [x] Экран группового чата

## Этап 6. Звонки

- [x] WebRTC 1-на-1, сигнализация через WebSocket сервера, шифрование DTLS-SRTP
- [x] TURN-сервер (coturn) для обхода NAT
- [x] Гудки, мелодия входящего, сигнал окончания
- [x] Push через Firebase на Android: входящий звонок и сообщения при закрытом приложении (iOS — с аккаунтом Apple)

## Этап 7. Видеозвонки

- [x] Видео поверх инфраструктуры этапа 6: видеозвонок из чата, камера включается и выключается в любой момент звонка, смена фронтальной и задней камеры, своё превью в углу, громкая связь по умолчанию

Этапы 4–7 детализируем, когда дойдём до них.
